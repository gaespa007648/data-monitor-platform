# 使用者與資料管理

## 帳號與角色

在 Streamlit「註冊」建立 User 帳號，再登入。帳號為 3–64 個英文字母、數字或底線，統一小寫；密碼至少 12、最多 256 字元。公開註冊不能指定角色。後端每次檢查 JWT 與資料庫帳號狀態；Admin 可在「系統管理」修改角色，變更在後續請求生效。

| 操作 | Admin | User | Viewer |
| --- | --- | --- | --- |
| 查看共享數據集與資料 | 可 | 可 | 可 |
| 建立數據集 | 可 | 可 | 不可 |
| 為數據集新增欄位、建立資料及批次匯入 | 全部數據集 | 自己建立的數據集 | 不可 |
| 查看使用者列表、修改角色、建立舊 API 分類 | 可 | 不可 | 不可 |

「系統管理」入口對所有登入者可見，非 Admin 進入後只會看到無權限訊息。後端 `GET /api/v1/users` 與 `PATCH /api/v1/users/{user_id}/role` 也各自檢查 Admin 權限；使用者列表 API 回傳總筆數與分頁資訊。角色限 admin、user、viewer，最後一位啟用中的 Admin 不可降權。

登入每來源 IP 每分鐘最多 30 次，註冊最多 10 次；超過回傳 429。限流目前是單程序記憶體視窗，透過 Streamlit 操作的使用者共用伺服器來源 IP 額度。

## 數據集 Schema 與記錄

Compose 首次啟動會從專案 `data/` 建立缺少的公開範例：`example-iris` 保留 `Id`、四個花萼／花瓣數值欄位與 `Species`，其中 `Id` 為 unique 整數；`example-vega-stocks` 含 `symbol`、`date`、`price`，股票 CSV 的原始日期會轉成 UTC datetime。兩者由停用登入的內部帳號持有，所有登入者可檢視，Admin 可管理。初始化只依完整名稱判斷是否建立；若已有同名數據集，即使其資料後來更動或刪除，也不會在重啟時重新匯入。

數據集在建立時包含 1–100 個自訂欄位。每欄可選填備註（最多 500 字元）及 data_type：string、integer、decimal、datetime、boolean；另可設定 required、nullable、unique（預設 false）。備註是欄位說明，不是資料記錄的值，也不參與資料型別驗證。欄名區分大小寫，不可重複；不可使用保留前綴 `__`。建立後，原欄位的名稱、備註、型別與規則不能變更或刪除，只能新增欄位；每次新增產生新的 Schema 版本。舊數據集欄位的 unique 預設 false；舊記錄保留當時的 Schema 版本，新欄位不回填。

手動建立資料時，後端依目前 Schema 驗證，通過才寫入。批次匯入須先選數據集，指定目前 Schema 版本及 CSV／JSON 檔案。預檢全檔不寫入；確認後再次驗證，包含 unique 欄位的同批及既有資料衝突檢查，資料、批次快照與稽核在同一交易提交。MariaDB 另以唯一索引防止並行寫入重複值。任何一列錯誤都不部分寫入。每檔最多 2 MiB、1000 筆資料；HTTP 請求另有 2 MiB 加 64 KiB 的上限。CSV 可選擇將第一列當欄名跳過，或不使用欄名、依 Schema 順序匯入每一列；JSON 頂層為物件陣列。完整頁面操作見 [Streamlit 前端操作手冊](streamlit-user-guide.md)。

「管理數據集」頁提供選擇數據集、整體欄位排序與分頁檢視，資料表固定每頁最多 10 筆，頁碼控制位於表格下方。「資料分析」頁提供欄位篩選、數值分布與摘要、分類聚合及時間趨勢，不顯示資料表；篩選僅作用於統計結果。所有登入者可讀取共享數據集。記錄可由建立者或 Admin 從管理頁表格直接刪除，後端刪除 API 會再次檢查權限；目前沒有更新功能。

## 既有固定四欄位 API

`/api/v1/records`、`/api/v1/record-imports`、`/api/v1/import-schemas` 與 `/api/v1/categories` 仍提供既有用戶端相容。此資料模型固定為 title、value、category_id、timestamp，不會自動轉進新數據集。舊記錄的更新／刪除仍限建立者或 Admin，Viewer 只可讀。固定欄位匯入範本及版本 API 仍有效，但新 Streamlit 頁面不使用它們。
